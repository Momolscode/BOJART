# Connecteurs Marwin depuis les échanges réseau

État du 30 octobre 2026. La brique `kalil0321/reverse-api-engineer` est retenue comme atelier de création de clients API pour les services qu'un connecteur, une API ou un SDK officiel ne couvre pas. Elle est distincte du REA d'analyse binaire déjà étudié.

## Ce qui fonctionne

- CLI Reverse API Engineer 0.14.0 installée dans un environnement Python isolé. Version, aide, dépendances et `agent --dry-run --headless --json` exécutés. Le précontrôle est OK avec un avertissement d'authentification du modèle ; cet accès n'est pas confirmé.
- `POST /connectors/inspect-har`, sous le jeton local existant, et l'outil MCP `connector_inspect_har` appellent le même module `reverse_api_adapter.py`.
- Le module extrait un contrat OpenAPI candidat par origine. Il conserve méthodes, chemins normalisés, noms des paramètres, types MIME et statuts observés ; pas les en-têtes, cookies, corps ou valeurs des paramètres. Les noms métier des chemins et paramètres demandent encore une revue.
- Une empreinte et un résumé sont enregistrés dans le journal SQLite existant. Le même import, après réouverture, retourne `duplicate`.
- Un test lit réellement `/health` sur notre API de boucle locale, vérifie son contenu typé, reconstruit une entrée HAR depuis cet échange et la soumet au nouveau point d'inspection. Deux soumissions donnent un seul événement. Il ne s'agit pas d'une capture faite par un navigateur RAE.

Aucun site tiers capturé, aucune session utilisateur récupérée, aucun client généré par un modèle ou exécuté automatiquement. Aucun appel LLM, crédit média, publication, achat ou commande de machine. Le précontrôle ne démontre pas l'authentification du fournisseur ni la robustesse face aux changements d'un site.

## Utilisation

Garder deux environnements : celui du pilote via `requirements-lock.txt`, et celui de RAE via `requirements-rae-lock.txt`. Cette séparation évite de modifier les dépendances de l'API existante.

Pour un HAR déjà autorisé :

```sh
python connector_cli.py capture.har --origin https://service.example --authority reference-du-mandat
```

La commande produit un contrat candidat, enregistre sa preuve et prépare la commande de précontrôle RAE si le binaire est présent. Elle ne lance pas RAE. Un HAR brut peut contenir des données privées : le garder hors des journaux et des livrables partagés.

L'origine doit être exacte. HTTP est réservé à la boucle locale explicitement demandée par `--allow-loopback`. Les endpoints d'écriture restent listés comme désactivés et ne sont pas inclus dans la proposition OpenAPI de lecture. Même un GET observé n'accorde aucune autorisation de l'exécuter.

```sh
python demo_reverse_api.py
python -m unittest discover -s tests -v
reverse-api-engineer agent --prompt 'Documenter les lectures autorisées' --url https://service.example --headless --dry-run --json
```

## Prochaine activation

Choisir un service utile dont l'API officielle ou le connecteur ne suffit pas, préciser les données attendues et l'accès autorisé, vérifier l'authentification et le plafond du run. Réutiliser une capture existante quand elle convient. Relire le client généré puis vérifier son résultat métier avant tout branchement à la file durable.

La console, UNUM et le poste personnel ne sont pas automatiquement raccordés par cet ajout. Le snapshot créatif embarqué et les anciens audits restent des exemples datés. La page de pilotage et la continuité actuelle conservent l'autorité sur les missions.
