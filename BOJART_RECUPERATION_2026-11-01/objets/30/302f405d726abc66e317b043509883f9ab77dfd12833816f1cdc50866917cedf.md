# BOJ.ART / JARVIS — dossier de lancement
Date : 20 octobre 2026. Projet distinct d’UNUM et de M-Tek.

## Pour la réunion avec l’associé
Ouvrir le PDF dans `04_Documents`, puis `01_Demonstration/DEMONSTRATION_BOJART.html` dans un navigateur.
La démonstration est autonome : pas de compte, d’installation ni d’accès Internet. Glisser pour tourner le vrai maillage, utiliser la molette pour zoomer, puis parcourir les étapes. Les flèches du clavier fonctionnent lorsque le modèle a le focus. « Lancer la visite » déclenche le parcours animé ; « Arrêter la visite » l’arrête.
Une politique de navigateur peut bloquer l’ouverture de fichiers locaux. Le PDF et les fichiers STEP/STL restent disponibles ; le responsable d’intégration pourra faire la présentation dans un environnement autorisé.

## Statut réel
- Nouveaux livrables : modèle CAO et ses exports, preuve géométrique, démonstrateur interactif, audit matériel renforcé, simulateur et tests, dossier de lancement.
- 22 tests exécutés sur le simulateur et les analyseurs d’inventaire, dans l’environnement de préparation.
- 7 contrôles de la démonstration réussis sous Chromium ; maillage affiché par une projection Canvas, pas par un moteur physique.
- Script Python exécuté sous Linux dans l’environnement de préparation. Script Windows non exécuté sur Windows.
- Aucun PC cible audité, aucun appel Jev ou LLM, aucun micro, slicer, imprimante ou compte social connecté.
- Aucun site existant modifié. Ce ZIP ne contient ni le code complet des sites V11, ni leurs bases de données ou tous les rushes.
- Ce pack n’est pas l’installateur final de l’atelier.

## Pour le responsable de l’intégration
Le propriétaire n’a pas à recopier de commandes. Utiliser les lanceurs d’audit dans `02_Audit_PC` une fois l’accès autorisé. L’audit observe la machine qui l’exécute ; un rapport de ce pack n’établit jamais les caractéristiques d’une autre machine.
Sur Windows, le lanceur utilise PowerShell sans contourner la politique d’exécution. Si la politique interdit le script, faire traiter l’autorisation via le parcours normal ; ne pas désactiver les protections globales.
Sur Linux, l’audit utilise Python 3 déjà installé ; son absence est signalée sans installer de logiciel.

Le protocole de reprise est dans `04_Documents/MISSION_REPRISE_CLAUDE.md`. Avant le déploiement, récupérer les sources complètes et les exports du journal/coffre des sites existants, puis tester leur restauration sur une copie.

## Fichiers 3D
`STL` : unités à interpréter en millimètres, avec manifeste associé.
`STEP` : CAO en millimètres.
`GLB` : géométrie mise à l’échelle en mètres.
Le socle est un exemple technique, pas une fixation porteuse certifiée. Le volume géométrique n’est pas une consommation de filament ou de résine après tranchage. Matériau, supports, jeu d’assemblage et charge restent à définir.

## Reproduction des contrôles (intégrateur uniquement)
`python 03_Preuve_Et_Tests/test_proof.py` exécute uniquement des tests dans des bases SQLite temporaires.
Le script `generer_socle.py` nécessite CadQuery 2.8.0 pour régénérer la CAO. Les exports fournis sont directement inspectables ; aucune installation n’est nécessaire pour les montrer dans le HTML.
Les tests de navigateur ont été exécutés à partir du HTML injecté dans Chromium ; l’ouverture via `file://` n’a pas été testée dans le navigateur administré de l’environnement.

## Sources et intégrité
Les références primaires et le registre du périmètre sont dans `04_Documents`. Le manifeste SHA-256 permet de repérer une altération des fichiers. Il ne constitue pas une signature d’éditeur ni une validation du contenu.
Aucun secret, jeton, compte client ou fichier de police n’est redistribué.
