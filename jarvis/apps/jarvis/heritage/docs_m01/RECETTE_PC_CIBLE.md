# Recette minimale sur le vrai PC — à effectuer par l’intégrateur

Les cases ci-dessous sont toutes à vérifier sur place. Aucun résultat du sandbox ne les remplace.

- [ ] Les sources et données actuelles des sites ont une copie vérifiée ; environnement distinct créé.
- [ ] OS / CPU / RAM / GPU / VRAM / stockage / affichages inventoriés.
- [ ] Les dépendances sont installées sans désactiver de protection globale.
- [ ] Les tests backend passent et le test direct navigateur/serveur conclut.
- [ ] La demande 180 mm et une variation 240 mm génèrent des fichiers différents, aux bonnes unités.
- [ ] Une demande comportant une charge ou un ordre machine non supporté n’est pas interprétée silencieusement.
- [ ] Un rechargement de page et une réponse perdue conservent le même reçu.
- [ ] Une sauvegarde est relue et restaurée dans un NOUVEAU dossier.
- [ ] L’interface reste lisible sur trois écrans et le moteur reste réactif en usage réel.
- [ ] Une modification de fichier est détectée ; un travail interrompu reste bloqué jusqu’à examen.
- [ ] Le modèle local et la voix seront testés sur un jeu français, bruit de l’atelier compris.
- [ ] Les opérations d’impression et de publication restent désactivées jusqu’à leurs recettes séparées.

## Indicateurs à mesurer, sans cibles inventées
Temps d’analyse de demande ; temps de CAO selon dimensions ; mémoire maximale ; délai de premier retour vocal quand la voix sera raccordée ; erreurs de cible/unité ; restauration complète ; qualité de découpe/contrôle sur pièces de référence ; temps humain de finition.

Le débit de génération dans l’environnement de préparation n’est pas une estimation de la tour. Un GPU coûteux ne rend pas automatiquement tous les modèles compatibles.
